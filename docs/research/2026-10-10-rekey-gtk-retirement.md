# WPA2 重密钥与旧 GTK 删除触发点（2026-10-10）

精读 IEEE 802.11-2024 12.6.19 全部对应文字（3034–3035），停止于 12.6.20 前。重密钥包含更新现有 SA 或创建同类新 SA；PMKSA 缓存与新 PTKSA 建立不是同一生命周期。PN Warning 为每个适用 SA 首次越阈的一次指示，允许 SME 提前触发更新，不等同于耗尽后的删除要求。

关键规则：GTK 更新后，AP 首次使用新 GTK 发送加密帧时删除旧 GTK；非 AP STA 首次收到新 GTK 加密帧时删除旧 GTK。两端触发不同，不能把握手完成作为统一删除时刻。Extended Key ID 支持时可先安装不同槽的新 PTK，再切换使用；每个分片组仍须使用同一 Key ID。Key ID 只识别槽/SA，不能代替稳定材料身份。

关联补读 CCS2018 6.4 全部对应文字（此前仅开头）：历史设备可能忽略 GTK 初始接收计数，导致重新连接后旧组帧可接受。该结论属于当时设备，不直接推断当前 AP；平台应保留对端携带的初始计数与真实配置计数的关联证据，不能默认所有组密钥从零开始。
来源：https://papers.mathyvanhoef.com/ccs2018.pdf

审查 core/model.py：安装历史跨槽/删除/会话保留，以稳定材料身份检测重装计数重置，符合前述原因；但当前没有 GTK 首次使用到旧 GTK 删除的专用状态和 AP/BSS 级组上下文。不能把每 peer 的泛用 key_deleted 事件当成该规则完整覆盖。后续应新增 BSS 组密钥代次、角色、首次使用和删除证据，而不是擅自让握手事件清理旧键。

本轮以 WPA2 标准和漏洞成因阅读为主，未修改执行代码、未测试、未发包。下一轮优先完善 GTK 更新规则的离线事件契约，再考虑接入内部插桩证据。
