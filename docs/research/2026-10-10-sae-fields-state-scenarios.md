# AP 状态测试：SAE 字段与场景判据

2026-10-10。此项服务于统一 AP 状态测试平台，手机热点只是测试对象之一。此前以“热点解析器”概括平台范围不准确；响应解码只是构造、收发、上下文关联及状态判断链路中的一个环节。

阅读范围：2024 标准印刷页 814–817 的认证帧格式与条件表、869 的 Send-Confirm 定义、870 的 SAE 字段定义、871 的群字段说明文字、1399 的 Password Identifier 定义、1436 的 Rejected Groups 定义、1437 的 Token Container 定义。页内无关条款未精读。817 已渲染视觉核对，其他图未视觉核对；871 图 9-182 未核对，群字段长度暂不登记为已核验。关联 9.2.2、9.4.2.1 编码规则及分配表仍待读。

表 9-71 表明条件字段取决于认证算法、事务和状态：SAE Commit 正常/H2E 携带 scalar/FFE；组拒绝、token 请求不能套用完整 Commit 结构；unknown-password-identifier 响应不能强制要求群字段。SAE transaction=2 还有建议 BSS 迁移的特殊拒绝分支，不能一律当作 Confirm 解析。Password Identifier、Rejected Groups、Token Container 都是带扩展 ID 的元素，不能当作无头原始字段。

## 从条款到平台场景（设计，尚未执行）

| 测试边界 | 构造/输入前提 | 响应观察 | 状态结论所需证据 |
|---|---|---|---|
| 正常 Commit | 已绑定双方身份、组、派生方法和当前运行 | 对端 Commit 的算法、事务、状态、字段结构 | 插桩确认群检查和 Commit 接受；报文结构本身不足 |
| 组不支持 | 保存当前实际提供的组及偏好历史 | 拒绝响应返回的组与本次请求是否匹配 | 匹配后才能判断重选组；无关旧拒绝不能推进新运行 |
| token 请求 | 保留原 Commit 与派生方式 | token 原始字节、封装、响应身份 | 当前运行重试语义，不能直接判认证失败；同运行重传与新运行分开 |
| 密码标识符未知 | 已知本次是否使用标识符 | 专用拒绝及可选标识元素 | 绑定当前请求后判断实例结束；不泄露密码或秘密 |
| Confirm | 保存双方 Commit 与计数器上下文 | 对端计数器和 Confirm 字节 | 内部验证结果及本地 Accepted；另需对端证据判断双方完成 |
| 特殊迁移拒绝 | 当前算法/事务与状态可识别 | Neighbor Report 分支 | 不把缺 Confirm 判成普通 Confirm 截断；后续迁移须另建目标上下文 |
| 无响应/截断 | 有发送、监听窗口和捕获质量证据 | 未见匹配响应或结构不完整 | 结果保留不确定性；需 AP 日志/状态判断是否按规范丢弃 |

这些场景尚未加入自主执行器，不能登记为已支持测试。现有 APModel 接受事件与原始帧观察必须继续分离。下一步读取编码约定后实现共用认证观察事件，再接入状态场景；不以一个 SAE 解码器代替平台目标。
