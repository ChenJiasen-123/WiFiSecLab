# GTK 退役事件检查模块（2026-10-10）

依据已精读 12.6.19 的角色差异，新增 lifecycle/gtk_retirement.py。公开 GtkRetirement API 绑定一个 BSS/epoch 和 AP/non-AP 角色，接收有证据引用的安装、加密发送/接受接收、删除和检查点事件。稳定材料身份不是无线 Key ID；合成状态与插桩状态禁止混合，pcap/probe 只记观察。

首次观察使用的材料建立 active；随后使用新材料才将旧 active 加入待删除集合。安装新材料本身不触发删除。检查点输出旧材料是否仍保留，但不宣称规范一致性：检查点时机、采集完整性和真实硬件删除仍须独立证明。旧材料回退不在本模块支持范围，明确拒绝交给其他分析。

限制：有序、串行更新的离线契约；没有接入当前只跟踪 pairwise cfg80211 操作的采集器，也没有 CLI 执行路径。未假装由帧推断内部接受。未来需要适配 BSS 组密钥操作与材料句柄，验证首个新 GTK 使用及删除返回的顺序。

更新目录功能说明，仅 AST 语法检查，未运行平台测试、未发包。此模块实现了前一轮记录的角色/触发差异，但并不表示整条 GTK 观测链已完成。
