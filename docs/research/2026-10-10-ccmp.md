# CCMP 离线完整性验证

阅读：IEEE 802.11-2020 12.5.3.3.2–12.5.3.4.4，印刷页 2492–2498（最后一节本轮读至 replay counter 初始化段，下一页未读）。使用既有镜像，未声称当前 2024 版全文已读。重点为 PV0 AAD 屏蔽、nonce 的 A2/优先级/PN 关系以及 MIC 成功才返回明文。PV1 文本已读但不实现。

对照来源：RFC 3610 https://www.rfc-editor.org/info/rfc3610/ 的 CCM 输入要求，cryptography 官方 AESCCM API https://cryptography.io/en/stable/hazmat/primitives/aead/ 。

新增 src/wifiseclab/ccmp.py：已知 PMK 的 SHA1 PRF 派生 TK、CCMP-128 单播完整性校验及解密。支持有限三地址 PV0 Data/QoS Data。要求明确 AP/STA、单播、Key ID 0、ExtIV、非零 PN；拒绝分片、HTC、A-MSDU、四地址、GTK、管理帧等上下文。解密函数返回敏感明文给调用者，默认验证记录只存摘要，不应记录任意用户负载。

实际抓包验证：最新自有 hwsim WPA2 实验中，五个单播帧通过 MIC；请求与响应负载尾部精确匹配该轮 UDP 随机标记。两个加密帧及已知实验口令派生的公开测试 PMK 固化为 fixtures/hwsim-ccmp.json，仅含隔离测试数据。

203 项测试通过：真实上下行样本、错误密钥、地址/PN/密文/tag 篡改、允许屏蔽字段变化、QoS TID 认证、未知格式拒绝。

范围：AESCCM 验证成功证明给定密钥下的密文与认证上下文匹配，不证明 AP 接收、密钥装入固件、重放被拒绝或隔离策略正确。本轮没有新无线发包。尚需整合 IPv4/UDP 严格解析与数据证据命令，并验证自定义握手实时链路；本轮未将子功能视作总目标完成。
