# OCV：信道上下文与实现前提

## 新读标准
完整阅读 12.2.10（2941–2942 页对应文字）。OCI 校验涉及 operating class 带宽、主信道、40 MHz 上下关系及 80+80 第二频段；不能只比较主信道号码。标准检查中的带宽关系是当前与对端收发所用最大带宽不大于收到 operating class 的带宽，而不是简单相等。OCT 情形还要区分期望的空口信道与隧道所用信道，不能混用本地监听网卡的信道作为目标 AP 信道。

本轮读到的 12.2.11、12.2.12 仅邻近文字，不计完成精读。Annex E operating class 映射、9.4.2.235 OCI 元素及 OCT 交叉引用尚未读完。

## 平台接入契约
需要明确：关联 epoch；本地 OCV 启用状态；对端经绑定的 RSNE OCVC；帧种类与方向；当前对端链路主信道、最大带宽、40 MHz 次信道关系、80+80 第二段；这些值的采集来源和有效时间；OCI 是否完整及经过对应消息保护验证。

缺少 operating class 映射或可信链路参数时结果应为 unknown，不能因 OCI 存在便判通过，也不能把未知 OCVC 当作未启用。目前 wnm.py 只保留尾部元素类型/长度，不提供 OCV 合规判定。
