# 四次握手 M3/M4 与实现注意事项

2026-10-10。续读 3069–3072，完成 12.7.6.4–6（M3 开头在前轮 3068 已读）。12.7.6.7 样例和 12.7.6.8 分析尚未读，整节仍不能登记全部完成。

M3 需要 ANonce 与 M1 一致、计数器未用过、MIC/AEAD 有效，并绑定广告 RSNE/RSNXE；OCV 和 SSID 保护有额外条件。无效 MIC 与计数器为静默丢弃，策略不匹配有断开处理，不能统一以无回应判断漏洞。第二 RSNE 可选覆盖语义仍需按范围处理。

M4 回显对应 M3 counter，AP 验证该值属于当前握手且大于当前会话已收非 Request 报文，然后验证 MIC/AEAD，才安装发送密钥并更新计数器。Extended Key ID 可使新接收密钥在 M3 前安装，因此“所有密钥都只能在 M4 后安装”是错误泛化；当前基线不支持扩展 Key ID，不扩称覆盖此路径。

12.7.6.6 规定有界重试及最终超时；不同句子的 shall/should 保留区别，尤其超时后的去认证不是随意统一成强制。ACK/Request 检查用于反射防护；未验证的 M1 不得更新正在使用的密钥状态。KCK/KEK 需为后续组密钥操作保留，关闭握手不等于销毁所有合法长期上下文。
