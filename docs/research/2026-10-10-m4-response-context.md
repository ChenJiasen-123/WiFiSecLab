# M4 的发送历史与已接受响应边界

2026-10-10。回查 IEEE 802.11-2024 12.7.6.2/3/4/5/6，印刷页 3066–3069、3071–3072 对应请求/响应和重放条款。此前完整阅读范围不变。此轮针对重试语义复读，不登记其他未读条款完成。

M2 的计数器应对应 outstanding M1。M4 则应是本次四次握手中 AP 用过的计数器，并严格高于本会话此前收到的非 Request EAPOL-Key。加上消息方向、当前阶段、MIC/AEAD 成功等前置检查，不能把任意历史计数器都当有效响应。因此，“必须等于最新发送值”对 M4 过严；“只要在历史里”又不足。M2 的 outstanding 语义仍需单独处理，不能直接套 M4 集合规则。

补读 USENIX2020 Cremers 等论文 3.5 Replay Counters（论文页 9–10，对应 PDF 索引 9–10），并连读 3.6 和 3.7 的文字：https://www.usenix.org/system/files/sec20-cremers.pdf 。论文区分数据加密层计数器与握手字段，说明 M2 和其他响应检查不同；其 nonce reuse 导致直接密钥泄露是最坏情况形式化抽象，不能把平台一次重复 nonce 观察直接表述成已恢复密钥。3.7 的线程队列、WNM 并发和仅跟踪最新组密钥等假设限制证明范围。此次不声明全篇读完、不声称重跑证明。

代码：core/model.py 增加 m3_counters（每轮握手发送历史）和 accepted_response_counter（会话接受响应边界）。当前 M3 阶段的重试计数器进入集合；M4 可以对应集合内较早 M3，同时须高于已接受边界。通过的 M2/M4 更新接受边界；新握手和断开清空 M3 集合，rekey 不清除会话接受边界，新会话创建新 Peer。覆盖快照与报告字段同步增加，防止不同上下文被覆盖统计合并。

例：抽象内部事件 M1(1)、M2(1)、M3(2)、M3(3)、M4(2)，满足 M4 历史匹配及大于 1 的边界，原先最新值相等规则会误报。M4(1) 或 M4(4) 则没有合格 M3 上下文。以上只是规则说明，未执行用例。

限制：handshake_message 是合成/内部接受断言，抓包和 probe 仍不会推进 AP 内部状态。当前模型没有独立原始接收与 MIC 验证事件；同阶段同计数器仍按重复观测处理，不据此证明 AP 接受了重放。多 M1 outstanding、发送计数器跨轮严格递增、Request 独立域、PMKSA 生命周期尚未完整实现。不得将此次修正描述为完整重放保护证明。
