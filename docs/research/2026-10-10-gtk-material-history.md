# GTK 删除历史与旧材料回归

## 标准复核
复核 IEEE 802.11-2024 12.6.19，印刷页 3034–3035。AP 在新 GTK 首次加密发送后删除旧 GTK；非 AP 在接收新 GTK 加密帧后删除旧 GTK。不能把组握手响应当成删除完成。3036 页读取了 12.6.20.1–.2 的当前页文字，后续跨页未读完，不计完整阅读。

## 文献复核
Vanhoef 与 Piessens，CCS 2018，Release the Kraken，6.3.2–6.4 对应文字。不同安装路径的历史关联以及安装时接收计数器处理，是不能只看当前 Key ID 的原因。本文历史设备结果不代表当前目标 AP；未复现实验，未完成全篇阅读。
来源：https://papers.mathyvanhoef.com/ccs2018.pdf

## 平台修改
GtkRetirement 增加已完成删除材料的历史集合；删除后重新安装同一稳定材料身份时记录线索，保留正常证据处理，不断言重放或计数器重置。无对应安装记录的删除事件拒绝作为完整状态输入。身份由采集端提供，不能使用可复用的线上 Key ID 代替。

只完成 AST 语法解析，没有运行 CLI、平台测试或无线实验。采集器尚未接入；输入窗口完整性、真实材料身份、硬件状态和计数器均未被证明。历史仅限当前 BSS/epoch，不能据此断言跨关联安全。
