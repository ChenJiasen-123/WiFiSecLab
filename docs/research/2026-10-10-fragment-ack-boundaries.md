# 分片重组规则与 ACK 证据边界（2026-10-10）

精读 IEEE 802.11-2024 10.4–10.5 全部对应文字（印刷页 1934–1936，止于 10.6 前）。发送同一片段的重传必须保持内容和长度；同一组片段使用相同序列号，片段编号从零递增。动态分片另受 26.3 覆盖，本轮未读该扩展。

10.5 已明确禁止不同密钥片段或密文/明文片段混合重组，这是核对历史 FragAttacks 4.1 根因时必须标明的版本变化。重组上下文还包括帧类型、发送/目的地址、序列控制、TID 和 More Fragments；仅同一 Key ID 不足以表示同一密钥材料。接收生命周期过期后后续片段仍应被 ACK 并丢弃，重复单播分片也应 ACK 后丢弃，所以 ACK 不能证明重组或数据接受。

代码：core/planning.py 的 protected_data 阶段补充完整性、上下文、接受证据和顺序边界；明确将分片覆盖标记为未实现，并列出后续必要不变量。没有构造或发送攻击片段，没有把计划义务当作实际覆盖。
