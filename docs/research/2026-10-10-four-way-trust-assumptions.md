# 四次握手的信任前提与证明边界

## 标准阅读
复核 12.7.6.8，印刷页 3074–3075 全部对应文字，结合此前 3073 页开头。PTK 派生绑定 AA/SPA 与双方 nonce；关于新鲜性和对端活性的结论以 nonce 随机选择及 PMK 信任前提为条件。重复看见 M1 并不能证明随机源失效，Key Replay Counter 单调也不能单独证明 PTK 新鲜。认证服务器与 PMK 交付身份绑定的信任不是无线四次握手自动可验证的属性。

标准提到 M4 为确认用途，并规定安装的顺序及 Extended Key ID 例外；分析段落不能替代具体状态机规定。平台不能从 M4 出现反推硬件已完成安装。

## 文献阅读
USENIX Security 2020，A Formal Analysis of WPA2，联网复核 3.7、4.1–4.2 对应文字（PDF 10–11 页），4.3 跨页未读完不计完整。3.7 的线程、队列顺序、并发协议和组密钥历史假设不能默认等同于真实 AP。4.2 的 PTK 保密性结论以对应 PMK 未泄露为条件，证明中特别纳入密钥重装与 nonce 重用；这不是单靠握手字段正确便可断言的性质。形式化模型中的强攻击者抽象也不表示所有 cipher 的 nonce 重用都实际泄露完整密钥。
来源：https://www.usenix.org/system/files/sec20-cremers.pdf

## 对平台结论的约束
1. 状态符合性、nonce 新鲜性、密钥保密性分开报告；没有发现状态异常不能推出密钥保密。
2. 一次采集内没有重复 nonce，不能证明随机生成质量，更不能证明整个设备生命周期从未复用。
3. 已知 PSK 的授权实验中研究者能派生 PTK 属于实验前提，不能作为 AP 泄密证据。
4. 关联 epoch、交换 ID、密钥材料和 MAC 参与者必须联合绑定；只看计数器或槽位不足。
5. FIFO、单线程串行和跨握手隔离均须被采集证明，不能直接从论文模型导入平台。

## 本轮结果
新增的是阅读与结论边界记录，没有新增代码、测试或无线实验。下一步继续读 4.3 与标准组密钥握手的 BSS 共享上下文，核对当前 per-peer 模型是否会把共享 GTK 当成互不相关的密钥。
